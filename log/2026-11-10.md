What changed: OpenCode gets the same agent hooks Claude Code and Codex have, mapped onto its plugin API by `.opencode/plugins/logHooks` (SessionStart on `session.created`/`session.compaction.started`, UserPromptSubmit on `session.hook("prompt")`, the two refusing hooks on `tool.execute.before`, PostToolUse on `tool.hook("execute.after")`, Stop on the `session.execution.*` events). Each answer is written where OpenCode actually delivers it, a `session.instructions.entry` under `log.hooks.start` or `log.hooks.live` (the system-part route is not delivered), with the prompt text and the tool result as fallbacks, and a refusal is thrown so the call fails with the hook's own words. A `log` tool reached through Code Mode's `execute` is found in its code, so Code Mode is hooked like a direct call. The session's log tool calls are written as a Claude-shaped transcript (`helpers/transcript.ts`) so the play reminder after compaction still finds the last `getGuide`, a child session's `parentID` is checked before the SessionStart block is given to it, and the first prompt of a session this plugin has not started posts `source: "resume"`. `src/agentHooks/opencode` holds the OpenCode install (merge the v1 `mcp.<server>` shape into `mcp.servers`, set `codemode: false` so log's tools are native, copy the hooks), `scripts/opencode/install.ts` runs it, both installers call it, and `log launch --setup` offers it as a Clack step. In `src/inbox/catchUp`, a chat the account cannot read (a 403 with Missing Access, 50001, Unknown Channel) no longer stops the whole catch-up: `chatRefusalIsLocal` skips it, keeps its position and reads the rest, and `notThePlatform` reopens a gap that only such a chat stopped. `WATCHER_CODE` now covers `src/inbox`, `src/platformKit` and `src/directApi`, so a change to an owner's own code restarts it instead of leaving it on old logic.
