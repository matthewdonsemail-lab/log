What changed: log.db's events are now the record and every typed row is derived from them. insertEventRow is the one way into events: appendEvent and the conversation import go through it, and it derives messages, attachments, chats, identities, memberships and interactions in the same transaction. A change is a new event, never an edit of an old one: attachmentsSeen (attachments found later, and the platform id when an older unkeyed copy is adopted), messageEdited (a text a read finds changed) and conversationSeen (a chat's box and members). A payload over 20,000 characters is kept whole, gzip-compressed, in blobs. The account's own id is written into events.ownerId when the event is appended, from a per-database tally of its conversation pairs, so a replay never guesses it. rebuildDerived replays every event into empty typed tables, verifyDerived does it on a scratch copy and compares row fingerprints, and the new command log storage verify|rebuild runs them. Migration 7 adds events.rawHash, ownerId and typedAt, attachments.path and error, and extenderVersion. The backfill types events older code left untyped, gives any typed row with no event an import event, and records text changed in place as messageEdited, the full scans once. chatMessages now reads the typed tables, and the conversation cache is stamped by the event log. REQ-STORAGE-04 to 06 cover it.
Why: matt: do the database work from the DDIA review (docs/storageAgainstTheBook.md, item 2: the event log is the system of record and every other table is derived from it). Before, full reads and the conversation import wrote typed rows with no event and edited text in place, addToPayload patched stored events, payloads were cut at 20,000 characters into invalid JSON, and deriving guessed the account's own id from whatever events existed at the time, so the typed tables could not be rebuilt.
Checked: On a copy of matt's log.db: migrations 6 and 7 took 45 ms, the one-time backfill 1.1 s (971 owner ids written, 5,175 events typed, 28 in-place edits recorded as messageEdited, no typed row without an event), each later open about 5 ms, and verifyDerived replayed every event into a scratch copy in 931 ms with every typed table identical. tsc, noComments, naming, agentHooks, docs, siteDocs and the spec anchors pass, and the full test suite passes, including the new derive.test.ts (reads append events, edits are events, blobs replay, owner id stored, rebuild and verify, orphan import) and storage.test.ts for log storage.
