What changed: Every platform now plugs in with an extender (`src/storage/platform`): `toChat`, `toIdentities`, `toMessage`, `toAttachments` and `toInteraction` turn the platform's own event into rows of the shared tables. `appendEvent` calls `typeEvent` in the same transaction as the event, so the watch, the catch-up and every read that appends land in the same rows: a message is keyed by its chat and the platform's own message id, so one pushed live and read again later is one row. Extenders exist for X, Discord, Slack, Instagram and Reddit (`EXTENDERS`), built on one shared `makeExtender`. X names the other side of a DM pair (colon or the older dash form) once the account's own id is known from its chats (`ownerIdFromPairs`), takes a group sender's bare id as the sender, and turns each notification into an `interactions` row and an identity. Slack's reactions are interactions. Discord server messages are channel chats with their server, and a reply points at the message it replies to. Attachments keep their kind (image, gif, video, audio, file, link) and a voice message's length. A sender with no id is kept by handle (`@name`), never dropped. Migration 3 (`typeStoredEvents`) types every event already in `log.db` once. The Discord, Slack and Instagram watchers stop dropping what their engines already send: the sender's id, the platform message id, what it replies to and the Discord server (Slack also keeps its attachments), so those platforms record people the way X does. `isBareId` moved into the storage helpers and the inbox store re-exports it.
Why: #97: one shape for every platform's data, through a platform extender, so a Discord voice message and an X Chat audio message are both one message and one audio attachment. matt: "work through both issues making commits with references to the issues".
